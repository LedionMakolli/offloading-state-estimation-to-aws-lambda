# Raw captures

Everything here is either captured verbatim from the Pico W's USB-CDC output or
from AWS, or generated by a script in this repository. Numbers quoted in the
top-level README come from these files.

| File | Source | What it is |
|------|--------|------------|
| `e3_results.txt` | Pico W, `e3_compute_profile` | E3 compute profile summary (cycles per operation) |
| `e3_raw.txt` | Pico W, `e3_compute_profile` | full E3 serial capture |
| `e4_results.txt` | Pico W, `e4_net_test` | E4a connection-stage timings, one run |
| `e4_raw.txt` | Pico W, `e4_net_test` | E4a, several consecutive runs |
| `e4b_results.txt` | Pico W, `e4b_mqtt` | E4b per-window round trips and summary |
| `e4b_analysis.txt` | `vimu-gen/e4b_analyse.py` | quantisation analysis of `e4b_results.txt` |
| `e4c_results_lazy.txt` | `cloud/lambda/estimator/e4c_return_leg.py` | E4c cloud-side breakdown, lazily created boto3 client |
| `e5_results.txt` | Pico W, `e5_rtos_jitter` | E5 summary: deadline latency under RSA load |
| `e5_raw.txt` | Pico W, `e5_rtos_jitter` | full E5 serial capture |
| `figures/` | scripts in `vimu-gen/` | every figure is regenerated by the script that names it |

## Redactions

The only edits made to captures are redactions: the account-specific AWS IoT
endpoint prefix is replaced by `<account-id>`, and the WiFi SSID, LAN IP and
resolved AWS IP by `<ssid>`, `<lan-ip>` and `<aws-ip>`. No measured value has
been changed.

## Two captures with Albanian labels

The summary block at the end of `e4b_results.txt` and all of
`e4c_results_lazy.txt` were printed by an earlier build whose report labels were
in Albanian. They are kept exactly as captured rather than re-typed, because a
measurement log that has been edited by hand is no longer a measurement log. The
per-window table in `e4b_results.txt` is in English, and the current firmware and
